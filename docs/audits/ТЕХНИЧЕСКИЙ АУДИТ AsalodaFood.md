
**Название:** AsalodaFood

**Ссылка:** https://www.asalodafood.by/

### Краткое описание ресурса

- **Назначение сайта:**
    Интернет-каталог с возможностью онлайн-заказа рационов здорового питания.

- **Основные возможности:**
    Выбор программ питания по калорийности, просмотр меню и состава блюд на каждый день, расчет КБЖУ, добавление рациона в корзину и оформление заказа, регистрация в личном кабинете, отправка форм обратной связи.
    
- **Целевая аудитория:**
    Жители Гродно, которые придерживаются ЗОЖ, следят за питанием и хотят сэкономить время на готовке.

- **Функции, полезные для нашего проекта:**
    Модуль выбора программ питания, интерактивное меню по дням недели, отображение КБЖУ и состава блюд, корзина, оформление заказа и форма обратной связи.

#### Логика работы

Сайт сделан по принципу разделения фронтенда и базы данных. При переходе по разделам страница не перезагружается полностью.

**Как происходит взаимодействие:**

1. Пользователь кликает на день недели или выбирает калорийность.
2. Браузер отправляет фоновый асинхронный запрос на сервер `api.asalodafood.by`.
3. Сервер возвращает данные в формате JSON.
4. Скрипт подтягивает эти данные и обновляет нужную карточку на экране.

**Основные API-эндпоинты (запросы к серверу):**

- `POST api.asalodafood.by/local` — отправка логина и пароля для входа.

- `GET api.asalodafood.by/me?populate=*` — получение данных авторизованного пользователя.

- `GET api.asalodafood.by/programs?filters...` — выборка программ питания с фильтрацией.

- `GET api.asalodafood.by/dishes?filters...` — получение списка блюд на конкретный день.

**Проблема с безопасностью:**
	При обращении к `/api/orders` сервер выдает данные заказа (адрес, телефон, имя) без строгой проверки авторизации. Из-за этого любой пользователь может увидеть чужие записи.
	_Рекомендация для нашего проекта:_ настроить проверку JWT-токенов на бэкенде, чтобы каждый пользователь имел доступ только к своим заказам.

### Технологический стек

 **Фронтенд:**
    - **CSS-фреймворк:** Tailwind CSS (в коде видны классы `flex`, `grid`, `z-50`, `rounded-full` и переменные `--tw-*`).
    - **Интерактивные элементы:** Swiper.js (используется для слайдера дней недели и меню).
    - **Шрифты и сервисы:** Google Fonts (Mulish, Noto Serif), Яндекс.Карты API.

**Бэкенд:**
    - **CMS:** Strapi (Headless CMS на Node.js). Это видно по структуре параметров в URL вида `?filters[program_type][$eq]=...` и `?populate=*`

### Семантические элементы HTML5

Страница представляет собой Single Page Application (SPA), собранное на JavaScript.

**Теги HTML5:**
    Явных семантических тегов (`<header>`, `<main>`, `<nav>`, `<footer>`) на странице почти нет. Вся верстка собрана на блоках `<div>`. Внутри `<body>` находится корневой `<div id="root">`, в который динамически подгружается весь контент. Из базовых тегов используются только служебные теги в `<head>` и `<noscript>`.

**CSS-классы:**
    Поскольку верстка сделана на `div`-ах, структура читается за счет понятных названий классов:
	- Поля ввода и кнопки: `.input-field`, `.input-label`, `.btn`, `.dropdown-menu`.
	- Слайдер: `.swiper`, `.swiper-wrapper`, `.swiper-slide`, `.swiper-button-prev`.
	- Обертки: `.container`, `.gradient-border`.

#### Адаптивность ресурса и медиа-запросы (@media)

Сайт адаптирован под разные экраны за счет медиа-запросов и утилит Tailwind:

- **Breakpoints для контейнеров:**
    
    - `@media (min-width: 320px)` — мобильные телефоны.
    - `@media (min-width: 640px)` — крупные телефоны и планшеты.
    - `@media (min-width: 768px)` — планшеты.
    - `@media (min-width: 1024px)` — ноутбуки.
    - `@media (min-width: 1280px)` и `@media (min-width: 1536px)` — десктопные мониторы.

- **Адаптация элементов:**
    
    - **Слайдер:** для кнопок `.swiper-button-prev` / `.swiper-button-next` пересчитываются размеры (`width: calc(...)`), чтобы они не перекрывали карточки на небольших экранах.
    
    - **Верстка категорий (Flexbox):** в блоке выбора программ используется `flex flex-wrap gap-5 justify-evenly`. На ПК карточки стоят в один ряд, а на маленьких экранах автоматически переносятся на новую строку.
    
    - **Сетка калорий (Grid Layout):** в блоке калорий заданы классы `grid grid-cols-1 md:grid-cols-2 lg:grid-cols-4 gap-4`. На мобильных карточки встают в 1 колонку, на планшетах — в 2, на ПК — в 4.

### Использование локального хранилища (Storage) и Cookies

В ходе анализа вкладки **«Хранилище» (Storage)** в DevTools установлены следующие механизмы сохранения данных клиента:

* **Cookies (`https://asalodafood.by`):**
  * `i18nextLng`: хранит код текущего языка интерфейса (`ru`).
  * `theme`: сохраняет цветовое оформление страницы (`light`).
  * Сторонние куки от домена `yandex.ru` (`_yasc`, `yandexuid`): хранят служебные идентификаторы счетчика Яндекс.Метрики.

* **Local Storage (`https://asalodafood.by`):**
  * `i18nextLng`: дублирует выбранный язык для работы библиотеки локализации `i18next`.
  * `translation_last_update` и `translation_version`: хранят метку времени последнего обновления и версию текстовых переводов. Это исключает лишние повторные запросы к серверу за языковыми пакетами при навигации.

### Заключение

В процессе анализа сайта `AsalodaFood.by` была изучена его структура, верстка и работа с бэкендом:

1. **Архитектура:** Это SPA-приложение на Tailwind CSS и Strapi CMS. Данные подгружаются асинхронно через REST API, поэтому сайт работает без лишних перезагрузок.

2. **Верстка:** Хотя сайт сверстан на `div`-ах без семантических тегов HTML5, код остается понятным за счет стилей Tailwind. Связка Flexbox и Grid делает интерфейс полностью адаптивным.

3. **Оптимизация:** На ПК сайт показывает высокую скорость (92/100 в Lighthouse). На мобильных производительность ниже (58/100) из-за несжатых фоновых картинок.

4. **Безопасность:** Была найдена уязвимость в `/api/orders`, из-за которой данные заказов доступны без авторизации. В нашем проекте нужно обязательно сделать проверку по JWT-токенам.
